# 004 번역 링크 · Google Scholar 링크

**날짜** 2026-10-08 · 사용자 요청 "번역 서비스 같은 거" → 1·2안(비용 없는 것)만 / "1저자와 교신저자의 기존 문헌을 구글 학술 검색에서"

## 번역 — 서버 없이

서버가 없어(002) 번역을 직접 하지 않는다. 길이 둘이다.

**① 브라우저 번역이 잘 되게.** 크롬·사파리·삼성 인터넷의 "페이지 번역" 은 이미 된다. 거슬리는
것은 사람 이름·세션 코드·시각까지 번역되는 것이다(Kim → 김, "Lee" → 리 같은). 그래서
`author`·`badge`·`code-tag`·`talk-time`·`conf-tag`·저자 줄·소속 목록에 `translate="no"` 를
달았다. 키워드·세션 제목·본문은 번역되게 둔다. 학회 자료에 `language`(BCP 47)를 더해
`<html lang>` 으로 낸다 — 브라우저는 이것과 기기 언어가 다를 때 번역을 제안한다.

**② 번역 사이트로 넘기는 링크.** 발표·초록 상세와 세션 소개에 Papago·Google 링크를 단다.
글은 `data-xlate` 를 단 요소(제목·본문)를 JS 가 모은다. 사이트마다 글자 한도가 있어
(Papago 3,000 · Google 4,500 으로 잡았다) 넘으면 문단 경계로 나눠 `1/2 · 2/2` 로 단다.
대상 언어는 기기 언어(`navigator.language`)에서 고르고, 상자나 설정 화면에서 바꾸면
`confoinfo_cfg.lang` 에 남는다. Papago 가 못 받는 언어면 Google 만 낸다.

**접힌 `<details>` 안에서는 `innerText` 가 빈 글이다** — 세션 소개의 번역 링크가 처음에 안
생겼다. 문단(`<p>`)의 `textContent` 를 모은다.

## Google Scholar — 링크만

Scholar 는 API 가 없고 자동으로 긁는 것을 막는다(약관 · CAPTCHA). 정적 사이트의 브라우저에서
가져오는 것도 CORS 로 안 된다. 그래서 **목록을 가져오지 않고 검색 링크를 단다** — 사람마다
"Profile"(저자 프로필 찾기 `citations?view_op=search_authors`)과 "Papers"(`author:"이름"`).

누구에게: 초록이 있으면 제1저자와 교신저자(같은 사람이면 한 줄에 역할 둘), 없으면 발표자
(직함 `Prof.`·`Dr.` 과 괄호 `(Convener: …)` 를 뗀다). 휴식·행사에는 없다. **동명이인을 가를
길이 이름뿐이라** 그 사람의 소속을 곁에 적고, 같은 이름이 섞일 수 있다고 한 줄 적었다.

페이지 안에 목록을 띄우는 길은 남겨 뒀다 — OpenAlex(무료 · 키 없음 · CORS 허용)를 누를 때
부르면 된다. 다만 흔한 이름(Kim·Lee·Wang)은 사람을 잘못 짚은 목록이 "이 사람의 논문" 처럼
보인다. 링크는 사람이 고르게 두는 것이라 그 위험이 없다.
