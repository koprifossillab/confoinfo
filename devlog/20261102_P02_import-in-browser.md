# P02 학회 자료를 브라우저에서 반입한다 (계획)

**날짜** 2026-11-02 · 사용자: "꼭 굽는 과정을 우리가 하지 않더라도, 사이트 이용자가 json 파일로 데이터를 임시로 반입해서
보이는 기능" · "우리가 json 파일 양식을 지정해주면, 사용자가 자기 인공지능에게 우리 repo 에 들어있는 지침에 맞게 파일을
가공하도록 하면, 여기서 반입을 해주는 거지" · "gsm-open repo 참고해봐"

## 흐름

1. 저장소에 **AI 가 읽을 지침**(`docs/ai-guide.md`, 영어)과 JSON Schema(`docs/confoinfo-1.schema.json`)를 둔다.
   사이트에도 구워 둔다(`format.txt` · `confoinfo-1.schema.json`) — 사용자의 AI 가 주소 하나로 읽게
2. 사용자는 자기 AI 에게 학회 프로그램(PDF·웹)을 주고 "이 지침대로 JSON 을 만들라" 고 한다. 반입 화면에 그 부탁 글을
   복사할 수 있게 둔다
3. 반입 화면(`/import/`)에 파일을 놓으면 **저장하기 전에** 읽은 것(학회·날짜·룸·세션·발표 수)과 오류·경고를 보인다.
   저장하면 이 기기의 IndexedDB 에 남는다. 서버로 가지 않는다
4. 반입한 학회는 `/local/?c=<slug>` 에서 프로그램 · 발표 상세 · 세션으로 보인다. 북마크는 구운 학회와 같은 자리에
   남고 내 계획에 합쳐진다. 첫 화면에도 "On this device" 로 뜬다

## GSM 개인 레이어(P08·118·130·131)에서 가져온 것

- **읽개 하나**(`static/conference/local.js`) — 반입 화면·반입 학회 화면·내 계획·첫 화면이 같은 코드를 쓴다
- **저장 전에 읽은 것을 보인다** — 오류가 있으면 저장하지 않고, 경고는 보이고 저장한다
- **IndexedDB** — localStorage 는 5 MB 남짓에 UTF-16 이라 STRATI(2.3 MB)가 위태롭다
- **저장 자료 관리** — 반입한 학회마다 열기·JSON 내려받기·지우기, 쓰는 저장소의 양, `navigator.storage.persist` 청하기
- 양식 예시는 손으로 따로 적지 않는다 — 지침 문서 하나를 저장소·사이트가 같이 쓴다

## 정한 것

- **받는 것은 `confoinfo/1` JSON 하나** — 저장소의 `conferences/*.json` 과 같은 형식, 같은 검사 규칙(`loader.validate` 를
  JS 로 옮긴다). CSV 는 사용자의 AI 가 JSON 으로 옮기면 된다
- **발표 pk 는 같은 식** — `sha1("slug/key")` 앞 13자리(`loader.stable_id`). 반입할 때 WebCrypto 로 계산해 둔다.
  나중에 그 학회가 정식으로 구워져도 북마크가 그대로 이어진다
- **이미 사이트에 있는 slug 는 받지 않는다** — 같은 학회가 두 번 뜬다. 정식 판을 쓰라고 알린다. 반입한 것끼리 같은
  slug 면 바꿔 넣는다(묻는다)
- **반입 학회 화면은 한 파일(`local/index.html`)이 쿼리로 가른다** — 서버가 굽는 화면은 경로로만 가르지만(002), 이
  화면은 브라우저 안에서만 그려지므로 쿼리가 괜찮다. 링크를 누를 때마다 새로 읽으니 앞뒤 단추가 그대로 돈다
- 프로그램 화면의 스크립트(룸 탭·스와이프·현재 시각 줄)를 `program.js` 로 빼서 두 화면이 같이 쓴다

## 뒤로 미룬 것

- 반입 학회의 검색·캘린더(.ics)·이름 한글 표시·번역·대표 논문
- 주소로 반입(남의 사이트의 JSON 을 바로 받기 — CORS 가 막는 곳이 많다)
- 반입 학회를 다른 기기로 옮기기 — 파일을 다시 넣으면 된다
